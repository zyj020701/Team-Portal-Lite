# RUM 告警规则

> 创建日期：2026-08-14
> 所属阶段：S9 — 接 RUM（真实用户监控）

---

## 1. 告警阈值

基于 Google Core Web Vitals 标准，当 P75（第 75 百分位）指标超过以下阈值时触发告警：

| 指标 | Good（绿色） | Needs Improvement（需改进） | Poor（差） | 告警阈值（P75） |
|------|-------------|---------------------------|-----------|----------------|
| LCP（最大内容绘制） | ≤ 2.5s | 2.5s ~ 4.0s | > 4.0s | **> 2.5s** |
| INP（交互到下一帧） | ≤ 200ms | 200ms ~ 500ms | > 500ms | **> 200ms** |
| CLS（累积布局偏移） | ≤ 0.1 | 0.1 ~ 0.25 | > 0.25 | **> 0.1** |
| FCP（首次内容绘制） | ≤ 1.8s | 1.8s ~ 3.0s | > 3.0s | **> 1.8s** |
| TTFB（首字节时间） | ≤ 800ms | 800ms ~ 1.8s | > 1.8s | **> 800ms** |

---

## 2. 告警级别

| 级别 | 触发条件 | 响应时间 |
|------|---------|---------|
| **P0 - 紧急** | P75 LCP > 4.0s 或 P75 INP > 500ms 或 P75 CLS > 0.25（进入 Poor 区间） | 30 分钟内响应 |
| **P1 - 严重** | P75 指标超过告警阈值但未进入 Poor 区间 | 2 小时内响应 |
| **P2 - 警告** | 单日 Poor 评级占比 > 10% | 24 小时内排查 |

| 渠道 | 用途 | 接入方式 |

## 4. 数据采集

- **采集工具**：web-vitals 库（onLCP / onINP / onCLS / onFCP / onTTFB）
- **上报方式**：`navigator.sendBeacon()` POST 到 `/api/vitals`
- **上报字段**：`name`、`value`、`rating`、`id`、`navigationType`
- **采样率**：教学项目 100% 采样；生产环境建议 10%~30%
- **数据存储**：教学项目打印到服务端控制台；生产环境建议接入 ClickHouse / BigQuery / 云监控

---

## 5. 监控看板建议

生产环境应搭建以下看板：

1. **P75 趋势图**：LCP / INP / CLS 的 P75 按小时/天趋势
2. **评级分布饼图**：Good / Needs Improvement / Poor 占比
3. **页面维度对比**：各路由的性能指标排名
4. **设备/网络维度**：移动端 vs 桌面端、4G vs WiFi
5. **地区维度**：不同城市/运营商的性能差异

---

## 6. 告警处理流程

1. 收到告警 → 确认指标和影响范围
2. 查看 RUM 数据，定位是全局问题还是特定页面/设备
3. 结合 Lighthouse 实验室数据复现问题
4. 制定优化方案并上线
5. 观察 RUM 数据是否恢复正常
6. 关闭告警，记录复盘

---

## 7. 避坑提醒

- **P09**：Lighthouse 分数高不等于真实体验好。RUM P75 才是最终验收标准。
- **P10⑥**：接了 RUM 但不看数据、不配告警等于没接。告警规则必须可执行。
- **P10①**：INP 在用户离开页面时才最终确定，必须用 `sendBeacon` 确保卸载时可靠发送。
