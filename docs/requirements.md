# Team Portal Lite —— 需求确认单

> 文档版本：v1.0  
> 创建日期：2026-08-12  
> 文档目的：在写任何代码之前，用"4 个问题"捋清需求，确保团队对项目目标有一致理解。

---

## 一、4 个问题

### 1. 给谁用？

本项目的目标用户是**内部团队成员**，具体包括三类角色：

| 角色 | 典型特征 | 核心诉求 |
|------|----------|----------|
| **普通团队成员** | 日常参与项目开发、需要了解团队动态 | 快速看到公告、自己的待办任务、本月寿星 |
| **新入职同事** | 刚加入团队，对项目和人员不熟悉 | 通过门户快速了解团队信息和工作安排 |
| **团队管理者/Leader** | 需要同步信息、跟踪任务进展 | 发布公告、查看任务整体完成情况 |

### 2. 解决啥痛点？

当前没有这个门户时，团队面临以下问题：

1. **信息分散**：公告散落在微信群、邮件、口头通知中，新同事无法回溯历史公告，老同事也容易遗漏重要信息。
2. **任务不透明**：每个人的待办任务只存在自己脑子里或本地笔记中，管理者无法快速了解谁在做什么、任务进度如何。
3. **团队归属感弱**：同事生日没有统一展示渠道，缺少团队温度；新人入职后难以快速认识团队成员。
4. **没有统一入口**：团队成员每天需要打开多个工具才能获取完整信息，效率低下。

### 3. 做成啥样？

核心界面是一个**单页团队门户首页**，包含以下核心区域：

| 区域 | 内容说明 |
|------|----------|
| **公告卡片** | 展示团队最新公告（标题、摘要、发布时间、发布人），按时间倒序排列 |
| **待办清单** | 展示当前用户的待办任务（任务名称、截止日期、完成状态），支持勾选完成 |
| **头像/寿星展示区** | 展示本月生日的同事头像和姓名，营造团队氛围 |

界面风格要求：
- 所有零件（公告卡片、待办清单、头像组件）风格统一，改一处全局同步。
- 页面布局清晰，信息一目了然，不需要复杂的导航和多级页面。
- 响应式设计，桌面端和移动端都能正常查看。

### 4. 怎么衡量成功？

以下标准全部满足，说明这个门户做成了：

1. **功能可用**：公告、待办、寿星三个模块都能正常展示数据，不是空壳页面。
2. **新人能上手**：一个新同事拿到代码后，按 README 操作能在 10 分钟内启动项目并看到首页。
3. **代码结构清晰**：任何开发者能在 5 分钟内找到"公告内容在哪里改""待办数据在哪里"，代码分层明确。
4. **架构可扩展**：后续添加新功能模块（如 Day22 的业务组件）时，不需要重构现有目录结构，在预留的业务零件层中直接添加即可。
5. **规范有保障**：ESLint 规则实际生效，跨层引用会被自动拦截，不依赖口头约定。

## 二、3 个核心用户使用场景

### 场景一：看公告

- **用户角色**：普通团队成员
- **操作路径**：
  1. 打开团队门户首页
  2. 页面顶部展示"公告卡片"区域
  3. 浏览最新公告标题和摘要
  4. 点击公告卡片查看完整内容
- **预期结果**：用户能在 3 秒内看到最新公告列表，点击后可查看公告详情，公告按发布时间倒序排列，最新公告在最上方。

---

### 场景二：看任务/待办

- **用户角色**：普通团队成员 / 团队管理者
- **操作路径**：
  1. 打开团队门户首页
  2. 在"待办清单"区域查看自己的待办任务
  3. 查看任务名称、截止日期和当前状态
  4. 完成任务后勾选对应复选框，标记为已完成
- **预期结果**：用户能清晰看到自己所有待办任务，按截止日期排序；勾选完成后任务状态实时更新；管理者视角能看到团队整体任务进展。待办数据在多个组件间保持一致，不会出现各存各的数据不一致问题。

---

### 场景三：看寿星（本月生日同事）

- **用户角色**：所有团队成员（尤其是新入职同事）
- **操作路径**：
  1. 打开团队门户首页
  2. 在"头像/寿星展示区"查看本月生日的同事
  3. 浏览寿星的头像和姓名
  4.（新同事）通过头像和姓名认识团队成员
- **预期结果**：用户能直观看到本月所有寿星的头像和姓名，展示区域风格与公告卡片、待办清单保持一致；如果本月没有寿星，展示友好的空状态提示。新同事通过此区域能快速认识团队成员，增强归属感。

## 三、模块独立性声明

根据架构约束，公告、待办、寿星这 3 个业务模块在代码层面必须**互相独立**：

- 公告模块不能直接调用待办模块的内部数据。
- 待办模块不能直接引用寿星模块的内部组件。
- 模块间如需共享数据，必须通过 `packages/lib` 中的公共出口或统一状态管理层共享。
- 每个模块的内部实现细节对外不可见，只通过统一出口暴露公共接口。

页面（`apps/web/app/page.tsx`）只负责**组装**这三个模块，不包含复杂业务逻辑，业务逻辑下沉到各自的业务零件层处理。
